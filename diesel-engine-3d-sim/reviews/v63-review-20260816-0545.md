# V63 复盘与验收记录 — 2026-08-16 05:45 CST

## 本轮定位到的阻断性缺陷
V59 的零红守卫本来要求连续 20 个 clean animation frame 后才 reveal，但 V60/V61/V62 每层 wrapper 在自己的 apply() 完成后都会调用 hideBoots()+reveal()。hideBoots() 会递归隐藏深层 V59 boot，因此后续 wrapper 实际绕过了 V59 的首屏零红门禁。也就是说，代码里虽然存在 V59 clean gate，但 V60+ 的页面仍可能在该 gate 完成前暴露场景。这与用户手机端持续看到粉红/红色遮挡的现象一致，是本轮最高优先级缺陷。

## V63 实施
新增 versions/v63-stable-readiness-barrier.html，继续保留 V62/V61/V60/V59 历史版本，不改项目外文件。

V63 不再信任任一外层 wrapper 的 reveal 状态，而是在最外层保留自己的不透明 boot，直到连续 30 次（80 ms 间隔）同时满足：
1. V59 __v59Debug.clean === true；
2. 当前最终 Three.js scene 中可见 Section/Cut overlay = 0；
3. 当前最终 scene 中可见红/粉材质 = 0；
4. V60 CAD Accessory root 存在；
5. V61 Cooling/Turbo root 存在；
6. V62 P–V canvas 已建立，且 pressureBar/tempK 为有限数。

每次 audit 还会主动关闭 Section/Cut 类对象、把残留红/粉材质中和为石墨灰/钢色，并隐藏低透明度暖红 Mesh。通过后仍持续审计，避免交互重新引入遮挡。
