# V59 Zero-Red Frame Guard — 复盘与验收记录

## 固定基准
- 首要基准：用户上传 `video_20260814_015807.mp4`，此前已抽取关键帧并记录：约 13.9 s 透明剖视+信息卡；23.1 s 系统拆解+散热器；32.4 s 裸机内部机构；41.7 s 深度爆炸+信息卡；右侧全程实时参数与 P–V 图。
- 补充基准：用户给出的 B 站 BV1kLgs6vETz / 短链 o4UzlBJ。本轮公开搜索没有可靠命中该 BV 号，因此不以搜索到的其他柴油机视频替代，也不声称完成该视频逐帧比对。

## 本轮阻断性缺陷
用户连续手机截图证明 V51 的红褐色铸件与红色剖切辅助几何仍可能在斜视角形成大面积粉色/红色遮挡。源代码证据：V51 使用 `0x852a25` 铸件材质和 `0xff3b30` section 材质，并在 cutaway 中把整块 casting 透明化，同时显示整块 section face。此前 V54–V58 均为后置清理层，存在异步加载/旧 handler 短暂重新启用对象的窗口。

## V59 实施
- 新版本：`versions/v59-zero-red-frame-guard.html`。
- 直接从 V53 当前工程层加载，不再串 V54–V58 修复包装层，减少一层以上异步竞争。
- 全场景规则：任何名称/父级命中 Section/Cut/Machined Section 的对象永久不可见。
- 所有可见材质按 HSL 扫描，红/粉色 `color` 强制改成石墨灰或钢色，红色 `emissive` 清零。
- V50 粗 block/head 永久隐藏；V51/V52 大型外壳在 cutaway 直接隐藏，不再使用半透明墙表达剖视。
- 旧 V49–V58 QA/ref 标签全部隐藏，避免遮挡与误判版本。
- 点击 cutaway/reset/explode/系统显隐时，capture phase 立即执行一次 scrub，并在下一 animation frame 再执行一次，降低旧 handler 重新开启红色对象的可见窗口。
- 首屏放行条件提高为：**20 个连续 requestAnimationFrame 审计均满足可见 overlay=0、red object=0、red material=0**。未达到条件则不移除 boot 层。
- 前 600 帧逐帧守卫；之后每 500 ms 长期复查。
- 运行状态写入 `window.__v59Debug`，版本角标只保留小型绿色 `V59`。

## 结论
本轮不报告“已经超过基准”。V59 的目标是先消灭当前最明确的阻断性 bug：任何红/粉半透明面、红色剖切面和红色破碎轮廓都不允许进入最终可见场景。代码已同步 GitHub，并把 `diesel-engine-3d-sim/index.html` 更新为 V59 默认入口。

## 后续最高优先级（在 V59 实机零红确认之后）
1. CAD-like 几何：飞轮壳、正时前盖/齿轮系、歧管法兰、管接头、附件支架和散热器细化。
2. 对照 `video_20260814_015807.mp4` 重新做同角度关键帧评分，尤其 13.9/23.1/32.4/41.7 s。
3. 对压力/温度/P–V 数据建立统一热力学状态源，验证图线、数字、缸内事件与曲轴角完全同步。
4. 在真实 iPhone/Safari 或 Android Chrome 做 5–10 分钟交互与 FPS 回归，记录最低 FPS、崩溃/卡顿和触控问题。
