## V36 复盘发现的阻断性逻辑缺陷
V36 新增冷却/润滑/高压燃油粒子流，但其显隐函数直接读取 `.systems .sys[data-system]` 是否具有 `active` 类。基础 UI 在“整机总览”时只有 `data-system="all"` 处于 active，因此 `coolant/oil/fuel` 三个具体系统元素均非 active，导致 V36 三类新增流体在默认“整机总览”状态下被错误隐藏。

这意味着 V36 虽然代码中存在粒子流，但默认画面不能可靠展示，故不能作为稳定验收版本继续沿用。

## V37 实施
1. 新建 `versions/v37-runtime-regression-flow-fix.html`，直接继承 V35 工业总成层，避免再叠加 V36 的错误显隐逻辑。
2. 重新实现冷却、润滑、高压燃油三类连续粒子流。
3. 新显隐逻辑同时读取：
   - 当前系统聚焦 `.systems .sys.active[data-system]`；
   - `#systemChecks input[data-vis=...]` 复选框状态。
   - 当 active 系统为 `all` 时三类流体默认全部可见；选择单独系统时只显示对应流体。
4. 默认仍强制正面剖视。
5. 新增自动运行时回归：
   - Three.js / canvas / P–V 是否存在；
   - V35 工业总成层和 V34 动态配气层是否存在；
   - 至少四个视角预设；
   - 流体粒子数量；
   - 默认总览时三类流动均可见；
   - 剖视按钮可双向切换并恢复；
   - 爆炸滑块 input 事件可触发并恢复；
   - 侧视→正视按钮可调用；
   - 切到 Fuel 时只保留燃油流，回到 All 后三类流体恢复。
6. 回归结果写入 `window.__v37Debug`，页面右下角展示 PASS/CHECK 状态。
