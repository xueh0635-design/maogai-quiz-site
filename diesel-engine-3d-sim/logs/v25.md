# V25 Mobile Boot Repair

## Trigger

User screenshots showed two distinct blocking regressions on mobile Chrome:

1. V23 reached the inner loader but remained on `正在载入 3D 引擎 / 正在尝试可用的 Three.js 镜像源`.
2. V24 regressed further and remained on the outer wrapper `V24 · 正在载入稳定引擎启动版…`, so the generated inner page was never presented.

## Root cause found this round

The first V25 wrapper that existed in the repository referenced `../vendor/three-r128.min.js` and `../vendor/OrbitControls-r128.js`, but the `diesel-engine-3d-sim/vendor/` directory does not exist in the repository. That implementation therefore could not be a valid stable entry.

## Implemented repair

- Replaced the broken V25 wrapper rather than creating another UI-only patch.
- Returned to the V23-style assembly path that had already been observed to reach the inner engine loader on the user's phone.
- Preserved V20 digital-twin geometry, V21 flow systems, V22 industrial hardware, and V23 smooth/deep explode choreography.
- Kept the widened V23 explosion vectors and staged damping animation.
- Replaced the primary Three.js r128 CDN URL with BootCDN, which exposes an r128 build and is typically more reachable from mainland/mobile networks.
- Replaced the primary OrbitControls r128 URL with the matching BootCDN path and retained an independent raw.githack fallback for the unpkg OrbitControls path.
- Removed the nonexistent local-vendor dependency.
- Added outer-wrapper progress text for all seven payload chunks so a future stall can be distinguished from the inner Three.js loader.
- Updated `index.html` so the default stable entry routes to repaired V25 build `v25-mobile-boot2`.

### Not yet reliably verified

- Pixel/visual comparison against the uploaded `video_20260814_015807.mp4` is not available in this automation runtime, so no claim of matching or exceeding the reference video is made.
