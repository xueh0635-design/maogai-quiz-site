# 四冲程柴油机 3D 仿真 — V4 迭代复盘

## 固定参考基准
- 用户上传视频：`video_20260814_015807.mp4`
- 复核关键帧：2 s、8 s、14 s、21 s、28 s、35 s、42 s、48 s
- 参考特征：四缸 1-3-4-2；透明/深度爆炸；独立系统显隐；细化配气机构；动态参数、P–V 图；工程信息卡；散热器/风扇/附件和大量管路。

## 本轮优先解决的三个差距
1. **D 配气机构机械真实性**：V3 的弹簧/摇臂/挺柱仍是“会动的示意件”，推杆没有完整同步运动，凸轮轮廓是缩放球体。
2. **E/G 四缸独立喷油、燃烧和进排气流动**：V3 有四缸相位，但流线主要还是共用路径，不能清楚看到“哪个缸此刻在吸气/排气/喷油”。
3. **K iPhone 与离线运行**：V3 每次都依赖 CDN；App 内置预览器可能直接拦截外部脚本。

## V4 实际修改
### D — 配气机构
- 新增完整 **摇臂轴 Rocker Shaft** 与 5 个摇臂轴支座。
- 每缸进/排气门新增：气门导管、上下弹簧座/锁片视觉件、真实螺旋弹簧、摇臂枢轴、推杆、挺柱和滚轮。
- `updateValve()` 现在同时驱动：气门位移、弹簧压缩、摇臂绕轴转角、推杆位移、挺柱/滚轮升程。
- 用 2D 凸轮极坐标轮廓 + ExtrudeGeometry 替换 V3 的“缩放球体凸轮”，8 个凸轮按各缸 720° 相位布置。
- 新增四套喷油器压板、喷油器安装井和气门弹簧座等缸盖服务面细节。
- 右侧实时增加 `1缸 IN / EX 气门升程`。

### E/G — 缸分辨喷油、燃烧与气体流动
- 每缸喷油由单一圆锥升级为 **6 束多孔喷油射流**。
- 每缸增加独立燃烧粒子云；喷射后至早期做功阶段随燃烧进度改变粒子尺寸、透明度和燃烧室颜色。
- 每个气缸分别建立独立进气支路、排气支路和高压燃油粒子流。
- 流线增加 `gate()`：进气流量由本缸进气门升程控制，排气由排气门升程控制，燃油由本缸喷油脉冲控制。
- 共用空气滤清器—增压器—中冷器总流路、共用排气总管、冷却与润滑循环仍保留。
- 流线透明度和速度继续受 RPM / 负荷共同影响。

### F — 深度爆炸进一步强化
- 爆炸模式不再只移动“配气机构整个系统”。
- 独立拆出：摇臂轴、八个气门总成、八个摇臂、八根推杆、八个挺柱与滚轮。
- 缸盖与配气部件采用不同爆炸距离，接近参考视频 21 s / 35 s 的层级拆解效果。

### K — 移动端与离线策略
- iPhone/iPad/Android 自动降低渲染像素比上限至 1.35，并把阴影图降至 1024，减少移动 GPU 压力。
- 增加手机轻触零件后固定信息卡的交互。
- 引擎启动改为 **cache-first**：首次联网成功后，把 Three.js r147 与 OrbitControls 源码缓存到浏览器 LocalStorage；后续同一浏览器可直接从本地缓存启动。
- 保留 fetch 失败 → classic `<script>` 标签回退，兼容部分 WebView 的 CORS 差异。
- 新增 **“生成离线版”** 按钮：在浏览器已经缓存引擎后，可把引擎源码内嵌到当前页面并导出 `diesel_four_stroke_3d_v4_OFFLINE.html`，得到真正不再请求 CDN 的单文件版本。
- 注意：我当前执行环境无法直接取得第三方 Three.js 文件字节并预打包进交付 HTML，因此交付的 V4 主文件首次运行仍需网络；真正自包含文件由页面的一键导出功能在首次成功运行后生成。

## 回归验证
### 代码级
- 两个 `<script>` 块均通过 `node --check`。
- DOM ID 检查无重复；唯一“缺失引用”来自动态 `cyl1..cyl4` 拼接检测的假阳性。
- 1-3-4-2 数学相位回归：
  - 0°：1 缸 POWER
  - 180°：3 缸 POWER
  - 360°：4 缸 POWER
  - 540°：2 缸 POWER
- 气门正时回归：0°附近存在轻微进排气重叠；约 90°进气升程接近峰值；约 630°排气升程接近峰值。
- 新增对象和路径均接受系统显隐/爆炸父级变换。

### 浏览器级限制
- 当前容器内 Chromium 受运行环境限制，`file://` 与 localhost headless dump 均未获得可用 DOM/截图；因此没有伪造“浏览器实测通过”。
- V4 已保留首帧就绪标志、超时错误页、网络/缓存双路径，并增加移动端降载，但仍需在真实 Safari/Chrome 做最终 WebGL 回归。

## 是否已经达到 / 超过参考
**否。** 目前主要差距已经不再是四冲程逻辑和 UI，而是：
1. 参考视频的机械总成整体更接近 CAD 外形，尤其壳体、法兰、齿轮、飞轮壳、附件支架和管接头；
2. 参考模型的透明件/实体件层次与几何边缘更成熟；
3. V4 主交付文件首次启动仍依赖一次网络获取 Three.js，虽然可以成功后“一键生成”真正自包含离线版；
4. 真实 iPhone Safari / ChatGPT 内置预览的 WebGL FPS 还没有实机证据。

## 下一轮最高优先级
1. **A/B CAD-like 外观**：重构缸体、缸盖、飞轮壳、正时齿轮、风扇叶片、歧管法兰与管接头，让整体轮廓从“程序化教学模型”进一步变成“数字样机”。
2. **透明剖视质量**：对固定机体做分区透明而非统一 opacity，并强化燃烧室/水套/油道之间的层次。
3. **发行工程**：如果能取得 Three.js 运行库原始字节，直接预打包一份真正自包含 HTML；否则继续保留 V4 的一键离线导出路径并优先做 Safari 实机回归。
