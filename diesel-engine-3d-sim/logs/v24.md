# 四冲程柴油机 3D 仿真 — V24 引擎启动修复记录

## 触发问题
用户在移动端实际打开 V23 后，页面长期停留在“正在载入 3D 引擎 / 正在尝试可用的 Three.js 镜像源…”。这说明 V23 的内层页面和 UI 已成功加载，但 Three.js / OrbitControls 的外部 CDN 启动链存在可靠性问题。

## 根因定位
V19–V23 共用的基础页面在每次启动时都通过 classic `<script src>` 依次请求 cdnjs、jsDelivr、unpkg，单源超时 6.5 秒；没有优先读取此前版本已经保存到 LocalStorage 的 Three.js 运行库。移动网络、VPN、WebView 或浏览器对跨域脚本请求不稳定时，会长时间停留在启动遮罩。

## V24 修复
1. 将引擎启动器改成 cache-first：先检查全局 THREE，再读取 `diesel-three-r128` / `diesel-orbit-r128`；同时兼容历史 V4 使用的 `diesel-three-r147` / `diesel-orbit-r147` 缓存。
2. 缓存不存在时改用 `fetch + AbortController` 获取脚本文本，每个源 4.2 秒硬超时，并在全局作用域执行；成功后写回 LocalStorage，后续启动不再依赖 CDN。
3. 网络回退仍保留 cdnjs、jsDelivr、unpkg，并新增 GitHub raw 源作为第四/第三回退路径。
4. 启动状态文字会明确显示当前处于“读取本机缓存”还是“网络源 x/n”，避免无反馈假死。
5. 所有源失败时不再长期卡在 loading：会显示明确的启动失败页，并提供“清除引擎缓存并重试”按钮。
6. V23 的顺滑深度爆炸动画、V22 工业附件、V21 流体、V20 数字样机主体全部保留。

## 静态验证
- V24 外层 wrapper JavaScript 已通过 `node --check`。
- loader 替换点已在解压后的 V19 基础 HTML 中确认存在：`(function loadEngineLibraries(){...`。
- V24 不修改柴油机项目以外的任何仓库文件。

## 未验证项
当前工具环境不能等价复现用户这台移动设备的具体网络/VPN/WebView 策略，因此不能声称所有移动网络下首次启动都已实测通过；但 V24 已消除“每次必须重新加载外部 Three.js 脚本”的设计缺陷，并恢复历史缓存兼容路径。
